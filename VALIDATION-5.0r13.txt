WaffleHouse-Client 5.0r13 validation
====================================
Baseline: WaffleHouse-Client 5.0r12 Desktop Bundle.

Changes validated:
- Top-level builder asks for target OS and individually selectable AIM/OSCAR, IRC, Telnet/BBS, SIP/VoIP, Media/Radio features.
- --protocols supports unattended feature selection; default unattended/all-feature behavior remains compatible.
- GUI connection picker only exposes enabled protocols; disabled SIP/Telnet tools and tray actions are hidden.
- CLI connection wizard advertises only enabled protocols; backend creation rejects disabled protocols.
- Disabled Media and SIP command families are rejected in CLI; disabled SIP commands are rejected in the GUI command path.
- Existing PJSIP multi-account limits remain >=32 accounts and >=50 calls; Asterisk chan_pjsip/standard and legacy chan_sip compatibility remain per-account.
- Telnet/BBS profiles persist exact columns/rows and auto-fit choice. GUI font fitting targets exact BBS character geometry; CLI sends exact NAWS geometry and requests terminal resize when supported.
- AIM/OSCAR client-created idle/away thresholds were removed. Actual elapsed idle seconds are sent using native OSERVICE 0x0001/0x0011; manual/server Away/AFK remains separate.
- OSCAR debug/audit selectors and credential-safe login/full wire logging from 5.0r12 are retained.

Validation executed in this Linux build environment:
- POSIX shell syntax: top-level, Linux/FreeBSD, macOS, PJSIP bootstrap builders PASS.
- 5.0r13 static regression: PASS.
- Existing macOS framework linkage regression: PASS.
- Existing macOS Qt deployment regression: PASS.
- Existing OSCAR debug/native-idle regression: PASS.
- Existing chan_sip compatibility regression: PASS.
- Existing SIP server-type UI regression: PASS.
- Top-level feature-routing dry run (AIM+IRC+Telnet enabled, SIP+Media disabled): PASS.

Environment limitation:
A native C++ link was not performed here because Qt6 development CMake packages are absent in this execution environment. Native Linux/FreeBSD/macOS target builds remain the final runtime/link validation.
