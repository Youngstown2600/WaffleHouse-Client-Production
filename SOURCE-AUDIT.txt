r12-r14 synchronization verified
--------------------------------
- r12 live audio-route polling/reopen behavior remains in the shared SipEngine.
- r13 runtime dial-prefix behavior is adapted per WaffleHouse SIP account rather than globally:
  * each saved SIP connection supplies the startup/default dial prefix;
  * each live PJSIP account has an independently changeable runtime prefix;
  * explicit sip:/sips: URIs, name-address values, and user@domain destinations are not prefixed;
  * GUI Buddy List and Softphone Main expose the runtime prefix;
  * CLI /prefix changes it, /dial applies it, /dialraw bypasses it, and /dialpreview shows the exact Request-URI.
- r14 FreeBSD detector script is copied byte-for-byte from S.I.P.H.E.R. r14:
  scripts/freebsd-hda-output-detect.awk
- r14 detector regression test is copied byte-for-byte and passes:
  tests/freebsd_audio_compat_test.sh
- Normal FreeBSD builds run the host audio preflight before managed PJSIP bootstrap.
- ./build.sh --audio-diagnose runs the host audio/HDA inspection read-only and exits without building WaffleHouse or PJSIP.
- ./build.sh --no-audio-fix keeps diagnostics while disabling automatic audio repair.

FreeBSD r14 repair guards
-------------------------
- Automatic Speaker/Headphones retasking is considered only for the detector's high-confidence topology:
  exactly one fixed Speaker + one jack Headphones output + no analog Line-out.
- The candidate uses the firmware Speaker association and Headphones sequence 15.
- Existing user-authored HDA hints for either candidate pin cause an automatic skip.
- WaffleHouse ignores only its own generated r14 block, or a S.I.P.H.E.R. r14 generated block,
  when deciding whether unrelated user HDA policy exists.
- PulseAudio is stopped only when a live HDA rebuild is actually attempted and is restarted afterward.
- Playback/capture PCM availability and the new runtime pin configuration are validated after reconfiguration.
- Failed validation immediately restores the previous runtime Speaker/Headphones pin configuration.
- No persistent generic Speaker/Headphones change is written until the runtime test succeeds.
- Persistence is a generated Headphones /boot/device.hints entry with a timestamped backup of the previous file.
- Complex/unrecognized output topologies remain advisory-only.
- The inherited narrowly fingerprinted ALC236 combo-jack microphone compatibility repair remains guarded separately.

2.5.1 multi-account integration and GUI hotfix
--------------------------------------
- SIP/VoIP is ConnectionSettings::Protocol::Sip alongside AIM/OSCAR, IRC, and Telnet.
- GUI Add Connection and CLI /add both create saved SIP accounts.
- Multiple SIP accounts share one PJSUA2 Endpoint and can register independently.
- Managed PJSIP 2.17 remains configured with PJSUA_MAX_ACC=32, PJSUA_MAX_CALLS=64,
  and PJ_IOQUEUE_MAX_HANDLES=256.
- Calls retain their owning SIP account ID/name through CallSnapshot.
- GUI Buddy List includes SIP account selection, runtime PBX prefix, Register, Disconnect,
  and Dial controls. Add SIP and Open Softphone were intentionally removed from the Buddy List.
- Tools now owns Open Softphone and Show Connections Window.
- Accounts is rebuilt per saved connection; AIM/IRC expose IM/Chatroom + buddy management,
  while SIP exposes local dial-contact management.
- The SIP backend now inserts its PJSUA2 account only after MainWindow state attachment,
  preventing the 2.5 constructor-time signal re-entry crash path during Add Connection.
- SIP add/start/register/update/disconnect paths contain unexpected PJSUA2 exceptions and failed add-account operations restore controller selection/profile state instead of leaking a half-added account.
- Active SIP calls remain child rows beneath their owning SIP account.
- GUI Softphone tabs remain: Main, Active Call, SIP Log, SIP Ladder, Profile, Activity.
- Softphone Profile edits the same saved WaffleHouse connection; there is no second credential database.
- CLI CALLS pane and the selected-connection workflow remain integrated.
- Runtime STUN list refresh, per-account unsaved passwords, and active-call edit/delete protection remain intact.

step. The source/builder validation above does not claim a completed native build.
